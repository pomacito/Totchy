# Встановлення на Android (PWA)

Застосунок — Progressive Web App: встановлюється з Chrome на Android без
Google Play та без окремого `.apk`. Реалізовано: `public/manifest.webmanifest`,
`public/service-worker.js`, іконки (`public/icons/`), офлайн-заглушка
(`public/offline.html`), реєстрація SW (`src/components/ServiceWorkerRegister.tsx`).

## Важливий нюанс: HTTPS обов'язковий (окрім `localhost`)

Service worker — а отже й повноцінна інсталяція PWA з іконкою на головному
екрані — реєструється браузером лише в «потенційно надійному контексті»:
`https://`, або `http://localhost`. **Звичайна локальна IP-адреса в межах
Wi-Fi (наприклад, `http://192.168.1.50:3000`) для Chrome на Android
НЕ вважається надійним контекстом**, навіть у межах однієї домашньої мережі.
Без HTTPS застосунок працюватиме в браузері як звичайний сайт, але Chrome,
найімовірніше, не запропонує «Встановити застосунок», а service worker не
зареєструється.

Нижче — два робочих способи перевірити реальну інсталяцію на телефоні,
маючи лише локальну мережу (без придбання домену чи хостингу).

## Спосіб 1 (найпростіший): тимчасовий HTTPS-тунель

На комп'ютері, де запущено `npm run dev` / `docker compose up` (порт 3000):

```bash
# варіант А — Cloudflare Tunnel (не потребує реєстрації)
cloudflared tunnel --url http://localhost:3000

# варіант Б — ngrok (потребує безкоштовного акаунта)
ngrok http 3000
```

Команда виведе тимчасове публічне посилання виду `https://xxxx.trycloudflare.com`
(або `https://xxxx.ngrok-free.app`). Відкрийте його в Chrome на телефоні —
з'явиться коректний HTTPS-контекст, service worker зареєструється, і Chrome
запропонує «Додати на головний екран» / «Встановити застосунок» через
меню (три крапки) або автоматичний банер.

Це не постійний хостинг — посилання діє, поки тунель запущено на комп'ютері,
підходить саме для демонстрації/перевірки встановлення.

## Спосіб 2: локальний HTTPS через самопідписаний сертифікат

Якщо не хочете відкривати доступ через тунель:

```bash
# встановлення mkcert (один раз, приклад для Ubuntu/Debian)
sudo apt install mkcert
mkcert -install
mkcert 192.168.1.50 localhost  # підставте реальну IP-адресу комп'ютера в мережі

# вкажіть next dev/start використовувати ці сертифікати, напр. через
# зворотний проксі (Caddy/Nginx) на порту 443, що проксує на localhost:3000
```

Далі на Android потрібно встановити кореневий сертифікат mkcert (файл
`rootCA.pem`, шлях виводить `mkcert -CAROOT`) як довірений — Налаштування →
Безпека → Встановити сертифікат. Це складніше за Спосіб 1, але не залежить
від зовнішнього тунелю.

## Кроки встановлення на самому Android-пристрої

1. Відкрийте HTTPS-адресу застосунку в Chrome для Android.
2. Зачекайте кілька секунд — Chrome покаже банер «Додати «Статус території»
   на головний екран» або аналогічний пункт з'явиться в меню (⋮).
3. Підтвердіть — на головному екрані з'явиться іконка застосунку (біла
   мітка-«пін» на синьому тлі), запуск відбувається в окремому вікні без
   адресного рядка браузера (`display: standalone` у маніфесті).
4. Перевірте офлайн-поведінку: увімкніть режим польоту — застосунок
   покаже чесну сторінку «Немає з'єднання з мережею» замість застарілого
   правового статусу (це навмисно: система ніколи не показує статус без
   дати актуальності, тому не кешує самі дані — лише іконки/шрифти/маніфест).

## Обмеження цього підходу (чесно)

- Це не нативний Android-застосунок і не з'явиться в Google Play. Якщо
  згодом знадобиться саме встановлюваний `.apk` зі списку застосунків
  пристрою — той самий маніфест і код без змін можна обгорнути через
  [Capacitor](https://capacitorjs.com/) або зібрати Trusted Web Activity
  через [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap); і те,
  і те так само вимагає публічного HTTPS-хостингу backend (тунель для
  демонстрації не підходить для тривалої публікації в Google Play).
- Backend (Next.js + PostgreSQL) повинен працювати весь час, поки
  застосунком користуються — PWA не працює offline-first із власною копією
  даних (свідоме рішення, щоб не показувати застарілий правовий статус,
  див. `docs/KNOWN_LIMITATIONS.md`).
- Push-сповіщення (Web Push) не підключені в цьому MVP навіть попри те, що
  PWA технічно це підтримує — модель `Subscription` у схемі закладена, але
  доставка — друга черга розробки.
