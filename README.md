# Статус території

Інформаційно-аналітична система для визначення офіційного правового статусу
населених пунктів і територіальних громад України відповідно до чинного
законодавства — з правовою підставою, датою актуальності та посиланням на
джерело для кожного висновку.

> **Це інформаційно-аналітичний інструмент, а не заміна офіційної юридичної
> консультації.**

## ⚠️ Демонстраційний режим цієї збірки

Середовище, у якому створювався цей MVP, не має мережевого доступу до
офіційних джерел (`zakon.rada.gov.ua`, `data.gov.ua` та інші урядові домени
заблоковані політикою мережі). Тому весь набір даних за замовчуванням —
**вигаданий, чітко позначений** (`isDemoData: true`), із навмисно
вигаданими географічними назвами (не реальні населені пункти України), щоб
виключити будь-яку плутанину з реальним правовим статусом реальних територій.
Детальніше — `docs/DECISION_LOG.md` та сторінка «Методологія» в самому
застосунку.

## Швидкий старт (Docker Compose)

```bash
cp .env.example .env
# за потреби відредагуйте .env — для docker-compose обов'язково задайте
# APP_SESSION_SECRET у своєму оточенні або .env (див. коментарі у файлі)
docker compose up --build
# в іншому терміналі, після старту контейнерів:
docker compose exec app npm run prisma:deploy
docker compose exec app npm run db:seed
```

Застосунок буде доступний на http://localhost:3000.

## Локальна розробка (без Docker)

Потрібен PostgreSQL 16+ з розширеннями `pg_trgm` і `unaccent`.

```bash
cp .env.example .env
# відредагуйте DATABASE_URL у .env за потреби

npm install
npm run prisma:migrate     # застосує міграції та створить БД, якщо потрібно
npm run db:seed            # завантажить демонстраційний набір даних
npm run dev                # http://localhost:3000
```

## Перевірка якості

```bash
npm run typecheck   # tsc --noEmit, strict mode
npm run lint         # ESLint
npm run test         # Vitest: unit (rules engine) + integration (API проти реальної БД)
npm run build        # production-збірка Next.js
```

Інтеграційні тести (`tests/integration/`) виконуються проти реальної БД —
перед запуском переконайтесь, що міграції застосовано і `db:seed` виконано.

## Структура проєкту

```
src/
  app/                 Next.js App Router: сторінки та API-роути
  components/          React-компоненти (UI)
  lib/
    rules-engine/       детермінований рушій визначення статусу (без LLM)
    search/              нечіткий пошук, транслітерація, дизамбігуація
    analytics/            обчислення аналітичної панелі
    reports/               генерація PDF (react-pdf) і CSV
    auth/                   сесії, хешування паролів, RBAC-guard
    storage/                 абстракція об'єктного сховища (local/S3)
    api/                       спільні response/rate-limit хелпери
  theme/               M3-подібна тема MUI (світла/темна)
prisma/
  schema.prisma        темпоральна/версійна схема даних
  seed/                 демонстраційний насіннєвий набір (чітко позначений)
tests/
  unit/                 rules engine — чисті fixture-тести
  integration/            API проти реальної БД
docs/
  DECISION_LOG.md        журнал архітектурних рішень
  ERD.md                  опис моделі даних
  RULES_ENGINE.md         специфікація рушія визначення статусу
  KNOWN_LIMITATIONS.md    чесний перелік обмежень цієї ітерації
  openapi.yaml            OpenAPI 3.1 специфікація публічного API
```

## Основні можливості MVP

- Розумний пошук (нечіткий, транслітерація, фільтри) з обов'язковою
  дизамбігуацією для однойменних населених пунктів.
- Картка території: точне формулювання категорії, дата початку/завершення,
  рівень запису (безпосередньо/успадковано від громади), нормативна підстава,
  посилання на джерело.
- Історичний режим («станом на дату») з коректним застосуванням тієї
  редакції нормативної бази, яка діяла на обрану дату.
- Порівняння до 10 об'єктів в одній таблиці.
- Аналітична панель з текстовими еквівалентами всіх графіків.
- Формування звітів PDF (кирилізований, A4, із застереженням і посиланням
  для перевірки) та CSV.
- Публічний журнал оновлень (diff між редакціями).
- Адміністративна панель: черга перевірки, підтвердження/відхилення з
  коментарем, rollback редакції без втрати історії, аудит-журнал.
- Публічне REST API з версією джерела та датою актуальності в кожній
  відповіді (`docs/openapi.yaml`).

## Резервне копіювання та відновлення

БД — звичайний PostgreSQL: використовуйте `pg_dump`/`pg_restore` за
стандартною процедурою вашої інфраструктури. Первинні файли джерел і готові
звіти зберігаються через абстракцію `src/lib/storage` (за замовчуванням —
локальний диск `STORAGE_LOCAL_DIR`, для production — підключіть S3-сумісне
сховище). Оскільки жоден історичний запис не перезаписується (`docs/ERD.md`),
відновлення з резервної копії БД не втрачає аудиторський слід чи попередні
редакції.

## Ліцензія шрифту в PDF-звітах

PDF-звіти використовують шрифт DejaVu Sans (`public/fonts/`, дозволена
ліцензія — див. `public/fonts/LICENSE.txt`) для коректного відображення
кирилиці, оскільки вбудовані шрифти PDF-рушія кирилицю не підтримують.
